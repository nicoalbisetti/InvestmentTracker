3. CAMBIO-1 — Porcentajes en DonutChart
=============================================================================

Archivo: frontend/src/components/charts/DonutChart.tsx

--- 3.1 Cálculo del total ---

Dentro del componente, calcular el total de los valores filtrados:

  const filtered = data.filter(d => d.value > 0);
  const total = filtered.reduce((sum, d) => sum + d.value, 0);

--- 3.2 Tooltip con porcentaje ---

Reemplazar el Tooltip actual por un CustomTooltip que muestre
el valor en BRL Y el porcentaje:

  const CustomTooltip = ({ active, payload }: any) => {
    if (!active || !payload?.length) return null;
    const item = payload[0];
    const pct = total > 0 ? (item.value / total) * 100 : 0;
    return (
      <div style={{
        background: '#fff', border: '1px solid #e5e7eb',
        borderRadius: 8, fontSize: 12, padding: '6px 10px'
      }}>
        <p style={{ fontWeight: 600, marginBottom: 2 }}>{item.name}</p>
        <p>{fmtBRL(item.value)}</p>
        <p style={{ color: '#6b7280' }}>{pct.toFixed(1)}%</p>
      </div>
    );
  };

Reemplazar <Tooltip formatter=... /> por <Tooltip content={<CustomTooltip />} />.

--- 3.3 Leyenda con porcentaje ---

Reemplazar el formatter de Legend para incluir el porcentaje junto al nombre:

  <Legend
    iconType="circle"
    iconSize={8}
    formatter={(value) => {
      const item = filtered.find(d => d.name === value);
      const pct = item && total > 0 ? ((item.value / total) * 100).toFixed(1) : '0.0';
      return (
        <span style={{ fontSize: 11, color: '#6b7280' }}>
          {value} <span style={{ color: '#374151', fontWeight: 500 }}>{pct}%</span>
        </span>
      );
    }}
  />

--- 3.4 Consideración de dark mode ---

El CustomTooltip usa colores hardcodeados para mantener el mismo patrón
que el resto de los tooltips del proyecto (fondo blanco, borde gris claro).
No hay cambio necesario para dark mode en el tooltip.

4. CAMBIO-2 — Agregar by_location en el backend
=============================================================================

Archivo: backend/app/routers/dashboard.py
Función: get_distribution()

Agregar una tercera query para agrupar por location, con el mismo patrón
que by_custodian (usando MonthlyPosition del snapshot más reciente):

  location_sums = (
      db.query(
          func.coalesce(Instrument.location, "brasil"),
          func.sum(MonthlyPosition.balance_brl)
      )
      .join(MonthlyPosition, MonthlyPosition.instrument_id == Instrument.id)
      .filter(
          Instrument.status == "activo",
          MonthlyPosition.date == latest_snap.date,
          MonthlyPosition.balance_brl.isnot(None),
          MonthlyPosition.balance_brl > 0,
      )
      .group_by(func.coalesce(Instrument.location, "brasil"))
      .all()
  )
  by_location = [{"name": loc, "value": v} for loc, v in location_sums if v]

Actualizar el return para incluir el nuevo campo:

  ANTES:
    return {"by_type": by_type, "by_custodian": by_custodian}

  DESPUÉS:
    return {
        "by_type": by_type,
        "by_custodian": by_custodian,
        "by_location": by_location,
    }

NOTA SOBRE CONSISTENCIA: by_custodian usa MonthlyPosition, pero by_type
usa Instrument.current_balance_brl. Esta inconsistencia ya existe en el
código actual y NO debe corregirse en este spec — es un cambio de mayor
alcance que queda para otra oportunidad. by_location usará MonthlyPosition
(mismo patrón que by_custodian) para ser consistente con las otras queries
que leen posiciones reales.

NOTA SOBRE EL GUARD: el return temprano del endpoint es:
  if not latest_snap:
      return {"by_type": [], "by_custodian": []}
Actualizarlo para incluir by_location:
  if not latest_snap:
      return {"by_type": [], "by_custodian": [], "by_location": []}
