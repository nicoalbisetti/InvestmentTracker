1. RESUMEN DE LA FUNCIONALIDAD
=============================================================================

Agregar al sistema InvestmentTracker la capacidad de importar proventos
(dividendos, rendimentos, JCP, pagamento de juros) desde la hoja
"Proventos Recebidos" del reporte mensual consolidado de XP/Santander.

La funcionalidad sigue el mismo patrón wizard de 3 pasos ya existente para
la importación de renta fija:
  Paso 1 → Configuración y upload
  Paso 2 → Preview de diferencias con lo que ya hay en la tabla Provento
  Paso 3 → Confirmación e importación

El sistema debe ser capaz de:
  - Parsear la hoja correctamente, incluyendo cantidades con formato brasileño
    (punto como separador de miles: "3.712,50" → 3712.50)
  - Hacer match entre el Produto del Excel y los Instrument registrados en la BD
  - Detectar proventos ya importados y mostrarlos como duplicados (no sobreescribir
    a menos que el usuario lo pida explícitamente)
  - Clasificar el tipo de provento según el "Tipo de Evento" del Excel
  - Agrupar en el preview por instrumento y por fecha de pago

2. ESTRUCTURA DE LA HOJA "Proventos Recebidos"
=============================================================================

- Nombre exacto de la hoja: "Proventos Recebidos"
- Headers en fila de índice 0 (pandas). Datos desde fila 1.
- Ignorar filas donde la columna 0 ("Produto") es NaN (son totales/separadores).
- El total global está en la última fila no-nula de la col 6 con label "Total"
  en col 5 — ignorar esa fila también.
- Total de proventos en Febrero 2026: 17 filas de datos.

Columnas (índice → nombre → descripción):
  0   Produto           Nombre del instrumento. Dos formatos posibles:
                          Formato A — Ticker: "MCRE11 - MAUÁ CAPITAL REAL ESTATE..."
                            El ticker es la parte ANTES del primer " - "
                            Ejemplos: MCRE11, XPML11, PETR4, IRIM11, VILG11
                          Formato B — Tipo: "CRI - OPEA SECURITIZADORA S/A"
                            Empieza con el tipo del instrumento (CRI, CRA, DEB, CFF)
                            No tiene ticker extraíble directamente
  1   Pagamento         Fecha de pago. Formato DD/MM/YYYY en el Excel.
  2   Tipo de Evento    Categoría del evento. Valores posibles (exactos):
                          "Rendimento"                    → type = "dividendo"
                          "Juros Sobre Capital Próprio"   → type = "jcp"
                          "PAGAMENTO DE JUROS"            → type = "jcp"
                          "PAGAMENTO DE PRÊMIO/RENDIMENTOS" → type = "dividendo"
  3   Instituição       Custodio. Normalizar:
                          "XP INVESTIMENTOS CCTVM S/A"    → "XP"
                          "BANCO SANTANDER (BRASIL) S.A." → "SANTANDER"
                          "INTER DISTRIBUIDORA..."        → "INTER"
  4   Quantidade        Cantidad de unidades sobre las que se pagó el provento.
                        ATENCIÓN: puede venir en formato brasileño con punto como
                        separador de miles: "3.712,50" → float 3712.50
                        También puede venir como número normal: 77, 173, 2900
  5   Preço unitário    Valor pagado por unidad en BRL.
  6   Valor líquido     Valor total neto pagado en BRL (= Quantidade × Preço unitário,
                        ya descontado IR cuando corresponde).
                        ESTE es el campo amount_brl a guardar en la tabla Provento.

4. CASOS ESPECIALES DEL PARSER
=============================================================================

CASO A — Formato numérico brasileño en Quantidade:
  "3.712,50" debe parsearse como float 3712.50 (NO como 3.71250).
  El punto es separador de miles, la coma es separador decimal.
  Aplicar esta conversión solo a campos numéricos cuando el valor es string.
  Función helper:
    def parse_br_number(val) -> float | None:
        if isinstance(val, (int, float)):
            return float(val)
        if isinstance(val, str):
            cleaned = val.strip().replace('.', '').replace(',', '.')
            try:
                return float(cleaned)
            except ValueError:
                return None
        return None

CASO B — Mismo instrumento, misma fecha, tipos distintos:
  PETR4 aparece DOS veces el 20/02/2026:
    - "Rendimento" → R$ 20.05
    - "Juros Sobre Capital Próprio" → R$ 1162.51
  Son dos proventos DISTINTOS del mismo instrumento en la misma fecha.
  La tabla Provento necesita la tupla (instrument_id, date, type) como clave
  de unicidad para el check de duplicados. NO usar solo (instrument_id, date).

CASO C — Instrumento sin ticker (Formato B):
  "CRI - OPEA SECURITIZADORA S/A" y "CRI - RIZA SECURITIZADORA S.A."
  No tienen un ticker directo extraíble. La estrategia de matching es:
    1. Buscar en Instrument donde name LIKE '%OPEA%' AND type = 'renta_fija'
    2. Si hay exactamente 1 resultado → usar ese instrument_id
    3. Si hay 0 o más de 1 → marcar como NO_MATCH en el preview
  El usuario puede asignar manualmente el instrument_id en ese caso.
  (Ver endpoint /map-instrument ya existente en la funcionalidad de RF)

CASO D — CFF en la hoja de Proventos:
  "CFF - KIJANI ASATALA FIAGRO-IMOBILIARIO" es un fondo de crédito.
  Mismo matching por nombre que CRI/CRA/DEB.

CASO E — Nombres de FIIs con variantes:
  "VILG11 - FII VINCI LG" en Proventos vs potencial "VILG11 - VINCI LOGÍSTICA FII"
  en la tabla Instrument. El ticker (VILG11) es suficiente para el match exacto.
  Siempre priorizar match por ticker cuando está disponible (Formato A).

CASO F — Validación del total:
  La hoja muestra Total = 8075.45.
  El parser debe calcular sum(Valor líquido) y comparar con el total del Excel.
  Si difieren en más de R$ 0.10 → incluir warning en el reporte de preview.
  En el archivo de Febrero 2026: sum = 8075.45 ✓ (coincide exactamente).

--- 6.1 Archivo: services/proventos_importer.py ---

Clase ProventosImporter:

  parse_excel(file_bytes: bytes) -> ParsedProventosReport
    - Leer hoja "Proventos Recebidos" con header=None
    - Usar iloc[0] como headers, datos desde iloc[1:]
    - Filtrar filas donde col[0] es NaN o col[6] es NaN
    - Filtrar la fila de "Total" (col[5] == "Total" o col[6] contiene solo el total)
    - Para Quantidade: aplicar parse_br_number()
    - Para Preço unitário y Valor líquido: aplicar parse_br_number()
    - Mapear Tipo de Evento → type interno:
        "Rendimento"                     → "dividendo"
        "Juros Sobre Capital Próprio"    → "jcp"
        "PAGAMENTO DE JUROS"             → "jcp"
        "PAGAMENTO DE PRÊMIO/RENDIMENTOS" → "dividendo"
        cualquier otro                   → "dividendo" + warning
    - Extraer ticker si Formato A (nombre empieza con ticker seguido de " - ")
      Formato A: el primer segmento antes de " - " tiene entre 4 y 7 caracteres
                 alfanuméricos y no empieza con "CRI", "CRA", "DEB", "CFF", etc.
    - Calcular suma total y comparar con el total del Excel
    - Retornar ParsedProventosReport

  compute_diff(parsed: ParsedProventosReport, db: Session) -> ProventosDiffReport
    - Para cada ParsedProvento:
        1. Match con Instrument:
           a. Si tiene ticker → buscar Instrument.ticker = ticker (exacto)
           b. Si no tiene ticker → buscar Instrument.name LIKE '%{keyword}%'
              donde keyword es la parte más distintiva del nombre del emisor
              (ej: para "CRI - OPEA SECURITIZADORA S/A" → buscar "OPEA")
           c. Si match exacto de 1 resultado → instrument_id encontrado
           d. Si 0 resultados → status = "NO_MATCH"
           e. Si >1 resultados → status = "AMBIGUOUS_MATCH", incluir opciones
        2. Si tiene instrument_id:
           a. Buscar Provento donde instrument_id=X AND date=fecha AND type=type
           b. Si existe y amount_brl igual (±0.01) → status = "DUPLICATE"
           c. Si existe y amount_brl diferente → status = "CONFLICT"
              (mismo evento pero monto distinto — puede ser corrección)
           d. Si no existe → status = "NEW"
    - Retornar ProventosDiffReport

  apply_import(diff: ProventosDiffReport, force_duplicates: bool,
               skip_codes: list[str], batch_id: str, db: Session) -> ImportResult
    - Ignorar items en skip_codes
    - Para NEW: crear Provento con todos los campos
    - Para CONFLICT: sobreescribir si force_duplicates=True, sino skip
    - Para DUPLICATE: skip siempre (a menos que force_duplicates=True)
    - Para NO_MATCH y AMBIGUOUS_MATCH: skip (requieren resolución manual)
    - Crear registro en provento_import_batches
    - Retornar conteos


Modelo Pydantic ParsedProvento:
  produto_raw: str           (texto original del Excel)
  ticker: str | None         (extraído si Formato A)
  nombre_busqueda: str       (keyword para búsqueda si Formato B)
  tipo_evento_raw: str       (Tipo de Evento original)
  custodian: str             ("XP" | "SANTANDER" | "INTER")
  fecha_pago: date
  cantidad: float | None
  precio_unitario: float | None
  amount_brl: float          (Valor líquido)
  type: str                  ("dividendo" | "jcp")

Modelo Pydantic ProventosDiffItem:
  status: Literal["NEW", "DUPLICATE", "CONFLICT", "NO_MATCH", "AMBIGUOUS_MATCH"]
  parsed: ParsedProvento
  instrument_id: int | None          (None si NO_MATCH)
  instrument_name: str | None
  instrument_ticker: str | None
  # Para CONFLICT:
  existing_amount_brl: float | None  (monto que ya hay en la BD)
  # Para AMBIGUOUS_MATCH:
  match_candidates: list[dict]       (lista de {id, name, ticker} posibles)
  warnings: list[str]

9. CRITERIOS DE ACEPTACIÓN
=============================================================================

  1. El parser procesa el archivo de Febrero 2026 y extrae exactamente
     17 proventos con un total de R$ 8.075,45.

  2. La cantidad "3.712,50" del CFF KIJANI se parsea correctamente como
     3712.50, no como 3.71250.

  3. Los dos proventos de PETR4 del 20/02/2026 (Rendimento y JCP) son
     tratados como DOS ítems distintos y se pueden importar ambos.

  4. El match para "CRI - OPEA SECURITIZADORA S/A" busca por nombre
     parcial ("OPEA") y si encuentra exactamente un Instrument → lo asigna.
     Si no lo encuentra → status NO_MATCH y el usuario puede asignarlo.

  5. Importar el mismo archivo dos veces marca los 17 ítems como DUPLICATE
     (no crea duplicados en la tabla Provento).

  6. Un ítem en estado CONFLICT (mismo instrumento/fecha/tipo pero monto
     diferente) no se sobreescribe a menos que force_duplicates=True.

  7. El DELETE /api/import/proventos/batch/{batch_id} elimina exactamente
     los N proventos del lote y no afecta otros registros.

  8. El campo import_batch_id permite trazar exactamente qué proventos
     entraron en cada importación.

  9. Los proventos importados aparecen correctamente en el cálculo de
     "Proventos YTD" del Dashboard.

  10. TASKS.md se crea antes de empezar el código y se mantiene actualizado
      durante todo el desarrollo.
