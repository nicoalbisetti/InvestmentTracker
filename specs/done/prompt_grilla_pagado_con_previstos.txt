FEATURE: Grilla de Pagado — Mostrar y sumar previstos no pagados
=============================================================================

## Objetivo

En la tab "Grilla pagado" de la página Proventos (`/proventos`), cuando una
celda (instrumento × mes) NO tiene pago registrado en `provento_items` pero SÍ
tiene una previsión en `provento_forecast`, mostrar ese valor previsto en un
color diferente (amarillo/ámbar), incluirlo en los totales de columna y fila,
y pre-popularlo en el input de edición cuando el usuario hace click.

La lógica es: si hay pagado → muestra pagado (verde, como hoy).
              si no hay pagado pero hay previsto → muestra previsto (ámbar).
              si no hay ninguno → punto gris (como hoy).

Esta feature no modifica ningún endpoint existente más allá de ampliar el
response del GET /api/proventos/grid para incluir datos de forecast.

PASO 1 — Backend: ampliar GET /api/proventos/grid
=============================================================================

### Archivo: backend/app/routers/proventos.py — función get_proventos_grid()

**Cambio requerido:** agregar datos de `provento_forecast` al response por celda.

La función actual devuelve por instrumento:
  {
    "id": ...,
    "name": ...,
    "type": ...,
    "months": { 1: <paid_amount|null>, 2: ..., ... },
    "total": <suma de meses pagados>,
    ...
  }

Debe pasar a devolver también `forecast_months`:
  {
    "id": ...,
    "name": ...,
    "type": ...,
    "months": { 1: <paid_amount|null>, ... },       ← sin cambios
    "forecast_months": { 1: <forecast|null>, ... }, ← NUEVO
    "total": <suma de meses pagados + meses solo previstos>,  ← CAMBIA
    ...
  }

**Lógica para forecast_months:**
- Cargar todos los ProventoForecast para los instrumentos y el año objetivo
- Para cada instrumento × mes: si months[m] es null (no hay pago) Y hay forecast
  para ese instrumento en ese mes → forecast_months[m] = forecast.amount
- Si hay pago registrado (months[m] > 0) → forecast_months[m] = null (no aplica)
- Es decir: forecast_months solo tiene valor donde months NO tiene valor

**Lógica para total (fila):**
- total = sum(paid para meses con pago) + sum(forecast para meses solo previstos)
- Es el mismo criterio "pagado si existe, si no previsto"

**Lógica para month_totals (totales de columna):**
- month_totals[m] = sum de (paid si existe, else forecast) para todos los instrumentos
- Reemplaza el cálculo actual que solo sumaba pagados

**Lógica para grand_total:**
- sum(month_totals.values())

**Patrón de queries a seguir** (ver /api/proventos/monthly como referencia):
1. Cargar paid items del año → paid_map: {(instrument_id, month): amount}
2. Determinar qué instrumentos tienen pago por mes → paid_insts: {month: set(inst_id)}
3. Cargar forecast del año → forecast_map: {(instrument_id, month): amount}
4. Al construir la respuesta por instrumento:
   - months[m] = paid_map.get((inst.id, m))
   - forecast_months[m] = forecast_map.get((inst.id, m)) if months[m] is None else None

**Sin cambios de schema de DB ni nuevos endpoints.**

**Cambios en el estilo visual de celdas:**

Actualmente hay dos estados: valor (verde) o vacío (gris).
Debe haber tres estados:

1. Pagado (months[m] != null):
   - Valor: fmtBRL(row.months[m])
   - Color: verde (clase actual: text-emerald-600 dark:text-emerald-400)

2. Solo previsto (months[m] == null && forecast_months[m] != null):
   - Valor: fmtBRL(row.forecast_months[m])
   - Color: ámbar (text-amber-500 dark:text-amber-400)
   - Agregar un indicador visual sutil que distinga que es previsto, no pagado.
     Opción sugerida: texto en ámbar con estilo italic o con un asterisco (*) al final.
     Ej: `{fmtBRL(val)}*`  — simple y claro.

3. Vacío (sin pago ni previsto):
   - Punto gris (·), igual que hoy

**Cambios en los totales:**

El endpoint ya devuelve month_totals y grand_total con la nueva lógica (incluye
previstos). El frontend no necesita recalcular totales; solo renderizarlos.

Sin embargo, los totales de columna en el header deben indicar visualmente si
incluyen previstos o son todo pagado. Implementación sugerida:
- Si month_totals[m] > paid_totals[m] → el total tiene componente previsto →
  mostrar en ámbar en vez de verde.
- Para esto, el backend también debe devolver paid_month_totals por separado,
  o el frontend puede calcularlo sumando solo rows.months[m].

Alternativa más simple (recomendada para no complicar): agregar al response
del backend un campo `paid_month_totals: {1: float, ...}` que sume solo lo
pagado por mes. El frontend puede comparar `month_totals[m] > paid_month_totals[m]`
para decidir el color del total de columna.

**Actualización optimista al guardar (saveCell):**

La lógica actual de saveCell actualiza `row.months[m]` localmente. Al guardar,
también debe limpiar `forecast_months[m]` en el estado local (porque una vez
guardado el pago, el forecast de esa celda ya no se muestra):

  const items = prev.items.map((row: any) => {
    if (row.id !== instId) return row;
    const months = { ...row.months, [month]: num || undefined };
    const forecast_months = { ...row.forecast_months, [month]: undefined }; // ← NUEVO
    const total = MONTHS.reduce((s, m) => s + (months[m] || row.forecast_months?.[m] || 0), 0); // ← recalcular con nueva lógica
    return { ...row, months, forecast_months, total };
  });
