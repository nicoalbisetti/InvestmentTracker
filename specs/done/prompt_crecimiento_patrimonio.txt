=============================================================================
1. CONTEXTO Y OBJETIVO
=============================================================================

La página /annual actual muestra una tabla y gráfico de barras apiladas con
diff, gain y net_flow por año. Es funcional pero no comunica claramente la
historia de crecimiento del patrimonio: ¿cuánto creció por decisiones del
inversor (aportes/rescates) vs. cuánto aportó el mercado (valorización)?

Esta feature reemplaza /annual completamente con una pantalla de "Crecimiento
de Patrimonio" con dos vistas:

  - Vista Anual:  tabla + gráfico histórico 2015–hoy, foco en composición
                  del crecimiento año a año
  - Vista Mensual: línea de patrimonio mensual para un año seleccionado,
                   con marcadores visuales de aportes y rescates


=============================================================================
2. LÓGICA DE DATOS — CÁLCULO HÍBRIDO
=============================================================================

El campo AnnualSummary.gain y .net_flow contienen datos importados del Excel
histórico (2015–primeros años de uso de la app). La tabla transactions contiene
movimientos reales registrados en la app, incompletos hacia atrás.

Regla de precedencia (aplicar en el backend, por año):

  txn_net_flow = SUM de transactions del año donde:
    - type = 'aplicacion' → sumar positivo
    - type = 'rescate'    → sumar negativo
    - amount_brl no nulo

  SI txn_net_flow != 0 (hay al menos una transacción ese año):
    → net_flow = txn_net_flow  (dato en vivo desde Transaction)
    → patrimonio_inicio = PortfolioSnapshot de diciembre del año anterior
      (total_with_prev o total_brl como fallback)
      Si no existe snapshot de diciembre anterior → usar AnnualSummary.total
    → patrimonio_fin = PortfolioSnapshot de diciembre de ese año
      (total_with_prev o total_brl)
      Para el año en curso: usar el snapshot más reciente disponible
    → gain = patrimonio_fin - patrimonio_inicio - net_flow
    → data_source = "calculated"

  SI txn_net_flow == 0 (sin transacciones ese año):
    → net_flow = AnnualSummary.net_flow
    → gain = AnnualSummary.gain
    → patrimonio_inicio = AnnualSummary.total (valor inicio almacenado)
    → patrimonio_fin = reconstruir desde PortfolioSnapshot si existe,
      sino calcular como patrimonio_inicio + net_flow + gain
    → data_source = "legacy"

Importante: un año con txn_net_flow == 0 puede tener rescates y aplicaciones
que se cancelan entre sí. Este es un caso borde que se acepta como limitación
documentada — la lógica es correcta en la gran mayoría de años.

--- 3.1 GET /api/annual ---

Sin parámetros query.

Lógica:
1. Obtener todos los AnnualSummary ordenados por year ASC.
2. Obtener todos los PortfolioSnapshot con mes = 12 (snapshots de diciembre)
   y el snapshot más reciente (para el año en curso).
3. Construir end_by_year: {año: total_with_prev o total_brl} desde snapshots.
4. Para el año en curso, si no hay snapshot de diciembre, usar el más reciente.
5. Para cada año en AnnualSummary, calcular txn_net_flow desde Transaction
   filtrando por fecha dentro del año (ene 1 – dic 31).
6. Aplicar la regla de precedencia del punto 2 para determinar:
   net_flow, gain, patrimonio_inicio, patrimonio_fin, data_source.
7. Calcular diff = patrimonio_fin - patrimonio_inicio (puede ser nulo si faltan
   snapshots en años legacy).
8. Calcular pct_growth = diff / patrimonio_inicio si patrimonio_inicio > 0.
9. Calcular pct_valorization = gain / diff si diff != 0 (proporción del
   crecimiento explicada por el mercado).

Respuesta JSON:
{
  "items": [
    {
      "year": 2024,
      "patrimonio_inicio": 1242000.0,
      "patrimonio_fin": 1489000.0,
      "net_flow": 80000.0,
      "gain": 167000.0,
      "diff": 247000.0,
      "pct_growth": 0.1989,
      "pct_valorization": 0.676,
      "data_source": "calculated"   // "calculated" | "legacy"
    }
  ],
  "metrics": {
    "total_invested": 980000.0,     // SUM(net_flow) de todos los años
    "total_gained": 867000.0,       // SUM(gain) de todos los años
    "gain_ratio": 0.885,            // total_gained / total_invested
    "cagr": 0.142                   // calculado desde patrimonio más antiguo
                                    // al más reciente, en años
  }
}

CAGR: (patrimonio_fin_ultimo_año / patrimonio_inicio_primer_año)^(1/n_años) - 1
donde n_años = diferencia en años entre el primer y último año con datos.
Si patrimonio_inicio_primer_año es nulo o 0, omitir cagr (null).


--- 3.2 GET /api/annual/monthly ---

Parámetro query: year: int (requerido)

Lógica:
1. Para cada mes del año (1–12), obtener el PortfolioSnapshot más cercano
   a {year}-{month}-01 con fecha <= ese día, LIMIT 1 ORDER BY date DESC.
   Si no existe → valor null.
2. Obtener todas las Transaction del año, agrupadas por mes.
   Por mes: net_flow = SUM(aplicacion) - SUM(rescate).
3. Calcular valorización acumulada del año:
   - base = patrimonio del snapshot de diciembre del año anterior
     (o primer snapshot disponible del año si no hay dic anterior)
   - Para cada mes: valorizacion_acum = patrimonio_mes - base - SUM(net_flow acumulado hasta ese mes)
4. Construir la lista de movimientos (transacciones individuales del año):
   para cada Transaction del año, incluir fecha, tipo, amount_brl, instrument_name.

Respuesta JSON:
{
  "year": 2024,
  "months": [
    {
      "month": 1,
      "patrimonio": 1300000.0,
      "net_flow": 0.0,
      "valorizacion_acum": 58000.0
    },
    ...
  ],
  "transactions": [
    {
      "date": "2024-03-15",
      "month": 3,
      "type": "aplicacion",
      "amount_brl": 40000.0,
      "instrument_name": "CDB XP 110% CDI"
    },
    ...
  ],
  "summary": {
    "patrimonio_inicio": 1242000.0,
    "patrimonio_fin": 1489000.0,
    "net_flow_total": 80000.0,
    "gain_total": 167000.0,
    "pct_net_flow": 0.324,    // net_flow_total / diff
    "pct_gain": 0.676         // gain_total / diff
  }
}

Para meses sin snapshot (null), el frontend mostrará el punto como vacío
(Chart.js spanGaps: false).
