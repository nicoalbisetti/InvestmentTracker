FEATURE: Simulación de Evolución de Cartera a Futuro
=====================================================

Objetivo: nueva página /simulacion que proyecta determinísticamente el valor
del portfolio a futuro, con inputs configurables por el usuario.

Decisiones de diseño confirmadas:
- Proyección determinística (tasas fijas por clase)
- 5 clases: renta_fija, accion, fii, fundo, internacional
- Aportes distribuidos proporcionalmente al peso actual de la cartera
- Defaults conservadores: RF=13% / Acc=12% / FII=10% / Fondos=11% / Intl=10%
- Nueva página /simulacion accesible desde el sidebar

Dependencias entre tareas:
- T-01 debe completarse antes de T-02..T-06 (frontend depende del contrato de API)
- T-02, T-03, T-04, T-05 pueden desarrollarse en paralelo una vez que T-01 esté listo
- T-06 depende de T-02..T-05
- T-07 es el último paso

T-01 — Endpoint backend GET /api/simulation
═══════════════════════════════════════════════

Crear nuevo router `backend/routers/simulation.py` e incluirlo en `main.py`.

--- Parámetros de query ---

| Param                    | Tipo  | Default | Descripción                                  |
|--------------------------|-------|---------|----------------------------------------------|
| horizon_months           | int   | 60      | Horizonte de proyección (1–120)              |
| monthly_contribution_brl | float | 0       | Aporte mensual en BRL                        |
| rate_renta_fija          | float | 0.13    | Tasa anual para renta fija (0.13 = 13%)      |
| rate_accion              | float | 0.12    | Tasa anual para acciones / ETFs              |
| rate_fii                 | float | 0.10    | Tasa anual para FIIs                         |
| rate_fundo               | float | 0.11    | Tasa anual para fondos                       |
| rate_internacional       | float | 0.10    | Tasa anual para activos internacionales (USD)|

--- Lógica del endpoint ---

1. Leer el snapshot inicial del portfolio:
   - Consultar la última MonthlyPosition para cada instrumento
     (MAX date GROUP BY instrument_id).
   - Convertir posiciones en USD a BRL usando el tipo de cambio actual
     (usar el campo `brl_value` si existe en MonthlyPosition, o bien
     `market_value_usd * usd_brl_rate`; consultar cómo está guardado en
     el modelo actual antes de implementar).

2. Agrupar por clase → obtener valor inicial por clase:
   - `renta_fija`:    instrumentos con tipo `renta_fija`
   - `accion`:        tipo `accion` y custodian != "XP INTERNATIONAL"
   - `fii`:           tipo `fii`
   - `fundo`:         tipo `fundo`
   - `internacional`: custodian == "XP INTERNATIONAL" (o el identificador
                      que use el codebase; verificar en CONTEXT.md)

3. Calcular proporciones iniciales de cartera:
   total_inicial = sum(valores por clase)
   proporcion[clase] = valor[clase] / total_inicial

4. Proyectar mes a mes (loop i = 1..horizon_months):
   - tasa_mensual[clase] = (1 + rate[clase])^(1/12) - 1
   - valor[clase][i] = valor[clase][i-1] * (1 + tasa_mensual[clase])
                       + monthly_contribution_brl * proporcion[clase]
   - total[i] = sum(valor[clase][i])

   Nota: las proporciones se mantienen FIJAS (las del snapshot inicial).
   La re-ponderación dinámica es una complejidad innecesaria para v1.

5. Construir respuesta:
   ```json
   {
     "snapshot_date": "2026-05-31",
     "initial_total_brl": 850000.0,
     "data": [
       {
         "month": 0,
         "date": "2026-06",
         "total": 850000.0,
         "renta_fija": 510000.0,
         "accion": 170000.0,
         "fii": 85000.0,
         "fundo": 59500.0,
         "internacional": 25500.0
       },
       {
         "month": 1,
         "date": "2026-07",
         ...
       }
     ]
   }
   ```
   El mes 0 es el estado actual (sin proyección), útil como ancla del gráfico.

--- Criterios de aceptación T-01 ---

- [ ] Endpoint responde 200 con todos los campos para parámetros válidos
- [ ] horizon_months fuera de rango [1,120] devuelve 422
- [ ] month 0 coincide con el valor real del portfolio según MonthlyPosition
- [ ] Con rate=0 y contribution=0, todos los valores permanecen constantes
- [ ] Con rate=0.12 y contribution=0, valor del mes 12 ≈ inicial * 1.12
      (error < 0.1% por redondeo de tasa mensual)
- [ ] Los aportes se distribuyen proporcionalmente (verificable: si renta_fija
      es 60% del portfolio, recibe 60% del aporte mensual)

T-02 — Hook frontend useSimulation
═══════════════════════════════════════════════

Crear `frontend/src/hooks/useSimulation.ts`.

```typescript
interface SimulationParams {
  horizon_months: number;
  monthly_contribution_brl: number;
  rate_renta_fija: number;
  rate_accion: number;
  rate_fii: number;
  rate_fundo: number;
  rate_internacional: number;
}

interface SimulationDataPoint {
  month: number;
  date: string;
  total: number;
  renta_fija: number;
  accion: number;
  fii: number;
  fundo: number;
  internacional: number;
}

interface SimulationResult {
  snapshot_date: string;
  initial_total_brl: number;
  data: SimulationDataPoint[];
}
```

- Usa `useQuery` de TanStack Query con `queryKey` que incluya todos los params.
- `enabled: true` siempre (los params tienen defaults).
- Debounce de 400ms en los inputs numéricos antes de disparar el fetch
  (usar `useDebounce` o implementar con `useEffect` + `setTimeout`).
- Stale time: 0 (siempre refetch al cambiar params).

--- Criterios de aceptación T-02 ---

- [ ] Hook exporta `{ data, isLoading, error }`
- [ ] Cambiar un param dispara refetch tras 400ms (no inmediatamente)
- [ ] isLoading es true durante el fetch
