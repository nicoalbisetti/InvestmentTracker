1. PARSEO DEL PDF
=============================================================================

Librería: pdfplumber
Instalación: pip install pdfplumber (agregar a requirements.txt)

Función principal: parse_xp_international_pdf(pdf_bytes: bytes) -> ParsedReport

El PDF tiene dos secciones a parsear:
  A) Tabla "CARTEIRA" — página 2
  B) Tabla "ATIVIDADE NÃO RELACIONADA À NEGOCIAÇÃO" — páginas 3-4

--- 1.A Parseo de CARTEIRA ---

Estrategia:
  1. Iterar páginas del PDF con pdfplumber
  2. En cada página, extraer tablas con page.extract_tables()
  3. Identificar la tabla CARTEIRA buscando una fila de header que contenga
     las palabras "Descrição" y "Quantidade" y "Preço"
  4. Procesar filas de datos. Ignorar la fila "Total".

ATENCIÓN — problema de símbolo+CUSIP:
  pdfplumber puede extraer símbolo y CUSIP como una sola celda con newline:
    "RDVY\n33738R506"
  o como dos filas separadas (la fila de CUSIP tiene todas las otras celdas vacías).
  Manejar AMBOS casos:
    Caso A — misma celda con \n: split por \n → linea[0]=symbol, linea[1]=cusip
    Caso B — fila siguiente solo tiene symbol en col1: mergearlo con la fila anterior

Función _merge_symbol_cusip_rows(raw_rows) -> cleaned_rows:
  Iterar raw_rows; si una fila tiene datos solo en col 1 (símbolo/CUSIP)
  y las demás columnas son vacías → es la fila de CUSIP del instrumento anterior.
  Mergear: prev_row.cusip = current_row[1]

Columnas esperadas (pueden variar por versión del PDF — usar índices relativos):
  0: Descrição
  1: Símbolo / CUSIP (ver nota arriba)
  2: Quantidade
  3: Ativos alugados (ignorar)
  4: Preço($)
  5: Posição atual
  6: Posição do período anterior
  7: Alteração %
  8: % Total da carteira

ParsedPosition (Pydantic):
  descricao: str              # "FORD MOTOR COMPANY 7.45%, 07/16/2031"
  symbol: str | None          # "RDVY"
  cusip: str | None           # "33738R506"
  quantidade: float           # face value (bonds) o shares (ETFs/equities)
  preco_usd: float            # precio unitario en USD
  posicao_usd: float          # valor de mercado = posição atual del PDF
  posicao_anterior_usd: float # posição do período anterior
  pct_carteira: float         # % del total
  asset_class: str            # inferido (ver sección 2)

Nota sobre precios de bonds:
  Para bonds: preco_usd es % del par (ej: 107.9701 significa 107.9701% del valor nominal).
  El valor de mercado = (quantidade_face_value * preco_usd / 100).
  VERIFICACIÓN: posicao_usd del PDF debe coincidir con ese cálculo ±0.01.
  Para ETFs/acciones: posicao_usd = quantidade * preco_usd directamente.
  El parser debe SIEMPRE usar la columna "Posição atual" como fuente de verdad
  del valor de mercado, no calcularlo, para evitar errores de redondeo.

--- 1.B Parseo de ATIVIDADE ---

Función: parse_atividade(pdf_bytes: bytes) -> List[ParsedDividend]

  1. Buscar tablas con header que contenga "Tipo de transação" y "Valor líquido"
  2. Filtrar SOLO filas donde tipo_transacao == "CASH_DIVIDEND"
  3. Ignorar "TRANSFER" (son migraciones internas, valor líquido = 0)
  4. Ignorar fila de "Total" si aparece

De la columna "Descrição" extraer con regex:
  Pattern: r"Cash Div of ([\d\.]+) on ([\d\.]+) shs\."
    → dividend_per_share: float, shares: float
  Pattern: r"Rec (\d{2}/\d{2}/\d{2})"
    → rec_date: date (formato MM/DD/YY → date)
  Pattern: r"Pay (\d{2}/\d{2}/\d{2})"
    → pay_date: date
  Pattern: r"(\d+)% NON Resident Alien Withholding"
    → withholding_rate: float (ej: 30 → 0.30)

ParsedDividend (Pydantic):
  pay_date: date
  rec_date: date
  symbol: str | None
  cusip: str | None
  shares: float
  dividend_per_share: float
  valor_liquido_usd: float    # columna "Valor líquido($)" del PDF — ya neto de withholding
  withholding_rate: float     # 0.30 en todos los casos del extrato de referencia

ParsedReport (Pydantic):
  period_start: date          # fecha inicio del extrato (2026-03-01)
  period_end: date            # fecha fin del extrato (2026-03-31)
  account_number: str         # "3XP83472" — parsear del header
  positions: List[ParsedPosition]
  dividends: List[ParsedDividend]
  total_portfolio_usd: float  # "Total" de la tabla CARTEIRA
  available_cash_usd: float   # "Saldo disponível" del RESUMO DA CONTA

Función parse_period_dates(pdf_bytes) -> (date, date):
  Buscar en la primera página el patrón "Data do extrato: YYYY-MM-DD - YYYY-MM-DD"
  Retornar (period_start, period_end)

3. MATCHING DE INSTRUMENTOS (usando campo ticker/codigo existente)
=============================================================================

Función: match_instrument(parsed: ParsedPosition, classification, db) -> MatchResult

El usuario configurará los instrumentos manualmente en la BD ANTES de importar:
  - Para bonds: instrument.ticker = CUSIP (ej: "345370CA6")
  - Para ETFs: instrument.ticker = ticker (ej: "RDVY", "VOO", "SPGP")
  En ambos casos custodian = "XP_INTERNATIONAL" y currency = "USD"

Estrategia de matching (en orden de precedencia):

  Paso 1 — Match por CUSIP (bonds):
    Si parsed.cusip:
      buscar Instrument donde ticker = parsed.cusip AND custodian = "XP_INTERNATIONAL"
      Si match exacto → status="EXACT", score=100

  Paso 2 — Match por symbol/ticker (ETFs):
    Si parsed.symbol Y no encontrado en paso 1:
      buscar Instrument donde ticker = parsed.symbol AND custodian = "XP_INTERNATIONAL"
      Si match exacto → status="EXACT", score=100

  Paso 3 — Match por symbol en instrument_code_mappings:
    (por si el usuario usó el wizard de mapeo manual en una sesión previa)
    buscar InstrumentCodeMapping donde codigo_excel = parsed.cusip OR codigo_excel = parsed.symbol
    Si match → status="MAPPED", score=100

  Paso 4 — Sin match:
    status="NEW"
    Si config.create_new_instruments=True → se creará automáticamente
    Si config.create_new_instruments=False → el usuario debe asignar manualmente

MatchResult:
  status: Literal["EXACT", "MAPPED", "NEW"]
  instrument_id: int | None
  match_key: str   # qué campo fue usado para hacer el match

4. TIPO DE CAMBIO USD/BRL
=============================================================================

En el Paso 1 del wizard el backend sugiere el rate automáticamente:

  Función: get_usd_brl_rate(reference_date: date) -> float:
    Intentar yfinance: yf.download("BRL=X", start=reference_date - timedelta(5),
                                             end=reference_date + timedelta(1))["Close"]
    Tomar el valor más cercano a reference_date (último día hábil disponible)
    Si falla → retornar None (el usuario deberá ingresarlo manualmente)

  reference_date = period_end (2026-03-31 para el extrato de referencia)

El usuario puede editar el rate sugerido. El rate ingresado se usa para:
  - Calcular balance_brl = posicao_usd * usd_brl_rate (posiciones)
  - Calcular amount_brl = valor_liquido_usd * usd_brl_rate (dividendos)
