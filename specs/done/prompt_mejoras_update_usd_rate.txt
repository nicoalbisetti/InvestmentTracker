2. CONTEXTO DEL CÓDIGO ACTUAL
=============================================================================

Archivo: backend/app/routers/positions.py
Función: update_usd_rate()

El comportamiento actual del endpoint es:

  a) Obtiene la cotización USD/BRL desde Yahoo Finance (yf.Ticker("USDBRL=X")).

  b) Itera todas las MonthlyPosition del mes target haciendo join con
     Instrument para obtener inst_location.

  c) Aplica lógica de rama:
       if inst_location == "exterior":
           mp.balance_brl = mp.balance_usd * usd_rate
       else:
           mp.balance_usd = mp.balance_brl / usd_rate

  d) Actualiza el PortfolioSnapshot manualmente:
       snap.usd_rate = usd_rate
       snap.total_usd = snap.total_brl / usd_rate

  e) Retorna:
       { updated, month, old_rate, new_rate, positions_updated }

sync_snapshot_for_date() ya existe en
backend/app/services/snapshot_sync.py y es usada por otros endpoints
(update_position_balance, copy_previous_month, etc.).

3. MEJORA-1 — Criterio de clasificación: usar currency, no location
=============================================================================

Archivo: backend/app/routers/positions.py

PROBLEMA:
  El código actual filtra por inst_location == "exterior" para decidir
  si una posición está denominada en USD. Pero el campo semánticamente
  correcto para esto es Instrument.currency. Un instrumento podría tener
  location != "exterior" y aun así currency == "USD" (o viceversa),
  produciendo un recalculo incorrecto.

CAMBIO REQUERIDO:
  Modificar el join para traer Instrument.currency en lugar de
  Instrument.location, y cambiar la condición de rama.

  ANTES:
    positions = (
        db.query(MonthlyPosition, Instrument.location)
        .join(Instrument, Instrument.id == MonthlyPosition.instrument_id)
        .filter(func.strftime("%Y-%m", MonthlyPosition.date) == target_month)
        .all()
    )
    for mp, inst_location in positions:
        if inst_location == "exterior":
            ...

  DESPUÉS:
    positions = (
        db.query(MonthlyPosition, Instrument.currency)
        .join(Instrument, Instrument.id == MonthlyPosition.instrument_id)
        .filter(func.strftime("%Y-%m", MonthlyPosition.date) == target_month)
        .all()
    )
    for mp, inst_currency in positions:
        if inst_currency == "USD":
            ...

No hay otros cambios en esta sección.

4. MEJORA-2 — Persistir usd_rate en MonthlyPosition
=============================================================================

Archivo: backend/app/routers/positions.py

PROBLEMA:
  El campo MonthlyPosition.usd_rate no se actualiza al ejecutar este
  endpoint. Otros procesos del sistema (por ejemplo, update-equities-prices
  para instrumentos USD) leen mp.usd_rate para recalcular balance_brl.
  Si usd_rate está stale en la posición, esos recálculos posteriores
  usarán una cotización incorrecta.

CAMBIO REQUERIDO:
  Dentro del loop de posiciones, asignar mp.usd_rate = usd_rate antes
  de cualquier otra operación sobre mp.

  ANTES:
    for mp, inst_currency in positions:
        if inst_currency == "USD":
            if mp.balance_usd is not None:
                mp.balance_brl = round(mp.balance_usd * usd_rate, 2)
        else:
            if mp.balance_brl is not None and mp.balance_brl > 0:
                mp.balance_usd = round(mp.balance_brl / usd_rate, 2)

  DESPUÉS:
    for mp, inst_currency in positions:
        mp.usd_rate = usd_rate                            # ← NUEVO
        if inst_currency == "USD":
            if mp.balance_usd is not None:
                mp.balance_brl = round(mp.balance_usd * usd_rate, 2)
        else:
            if mp.balance_brl is not None and mp.balance_brl > 0:
                mp.balance_usd = round(mp.balance_brl / usd_rate, 2)

5. MEJORA-3 — Reemplazar actualización manual del snapshot
=============================================================================

Archivo: backend/app/routers/positions.py

PROBLEMA:
  El código actual actualiza el PortfolioSnapshot a mano:
    snap.usd_rate = usd_rate
    snap.total_usd = snap.total_brl / usd_rate
  Pero no recalcula snap.total_brl. Si algún instrumento exterior cambió
  su balance_brl (porque recalculamos desde balance_usd × nueva cotización),
  el total_brl del snapshot queda desactualizado, afectando los KPIs del
  dashboard.

  sync_snapshot_for_date() ya resuelve esto correctamente: recalcula
  total_brl sumando todos los MonthlyPosition del mes, y luego recalcula
  total_usd = total_brl / usd_rate. Es exactamente lo que se necesita.

CAMBIO REQUERIDO:
  Reemplazar el bloque manual de actualización del snapshot por:
    1. Solo guardar el usd_rate en el snapshot (para que
       sync_snapshot_for_date lo pueda usar al calcular total_usd).
    2. Llamar db.flush() para que las modificaciones de las posiciones
       sean visibles dentro de la misma transacción.
    3. Llamar sync_snapshot_for_date(db, target_date).
    4. Llamar db.commit() al final.

  Verificar que sync_snapshot_for_date esté importada en el archivo.
  Ya se importa en otros endpoints del mismo router; si no estuviera,
  agregar el import desde backend/app/services/snapshot_sync.py.

  ANTES:
    old_rate = None
    if snap:
        old_rate = snap.usd_rate
        snap.usd_rate = usd_rate
        if snap.total_brl:
            snap.total_usd = snap.total_brl / usd_rate
    db.commit()

  DESPUÉS:
    old_rate = None
    if snap:
        old_rate = snap.usd_rate
        snap.usd_rate = usd_rate           # necesario para sync_snapshot
    db.flush()
    sync_snapshot_for_date(db, target_date)
    db.commit()

  NOTA: target_date es el objeto date del mes procesado. Construirlo así
  antes del bloque de snapshot, si no existe ya en la función:
    from datetime import date as date_type
    target_date = date_type(int(target_month[:4]), int(target_month[5:7]), 1)

6. MEJORA-4 — Enriquecer el response con conteo desglosado
=============================================================================

Archivo: backend/app/routers/positions.py

PROBLEMA:
  El response actual solo incluye positions_updated: N sin distinguir
  cuántas posiciones se procesaron por cada rama ni cuántas quedaron
  sin actualizar por falta de datos.

CAMBIO REQUERIDO:
  Agregar tres contadores en el loop y devolverlos en el response.

  Declarar antes del loop:
    usd_recalculated = 0
    brl_recalculated = 0
    skipped_no_balance = 0

  Dentro del loop, incrementar según el caso:

    mp.usd_rate = usd_rate
    if inst_currency == "USD":
        if mp.balance_usd is not None:
            mp.balance_brl = round(mp.balance_usd * usd_rate, 2)
            usd_recalculated += 1
        else:
            skipped_no_balance += 1
    else:
        if mp.balance_brl is not None and mp.balance_brl > 0:
            mp.balance_usd = round(mp.balance_brl / usd_rate, 2)
            brl_recalculated += 1
        else:
            skipped_no_balance += 1

  Actualizar el return al final de la función:

  ANTES:
    return {
        "updated": True,
        "month": target_month,
        "old_rate": old_rate,
        "new_rate": round(usd_rate, 4),
        "positions_updated": len(positions),
    }

  DESPUÉS:
    return {
        "updated": True,
        "month": target_month,
        "old_rate": old_rate,
        "new_rate": round(usd_rate, 4),
        "positions_updated": len(positions),
        "usd_recalculated": usd_recalculated,
        "brl_recalculated": brl_recalculated,
        "skipped_no_balance": skipped_no_balance,
    }

  NOTA: El frontend (Positions.tsx) actualmente muestra old_rate y new_rate
  en el toast de resultado (usdResult). No es necesario actualizar el
  frontend para que funcione, pero si se quiere mostrar el desglose en el
  toast, los campos nuevos ya estarán disponibles en usdResult. No modificar
  el frontend en esta tarea — dejarlo como mejora opcional futura.

8. CRITERIOS DE ACEPTACIÓN
=============================================================================

[ ] Al llamar POST /api/positions/update-usd-rate, las MonthlyPosition de
    instrumentos con currency="USD" recalculan balance_brl desde balance_usd.

[ ] Las MonthlyPosition de instrumentos con currency="BRL" (o distinto de
    "USD") recalculan balance_usd desde balance_brl.

[ ] Todas las MonthlyPosition del mes procesado tienen mp.usd_rate igual
    al nuevo rate obtenido de Yahoo Finance.

[ ] El PortfolioSnapshot del mes tiene total_brl recalculado como sumatoria
    real de los balance_brl de las posiciones del mes (no el valor anterior).

[ ] El response incluye los campos: updated, month, old_rate, new_rate,
    positions_updated, usd_recalculated, brl_recalculated, skipped_no_balance.

[ ] El endpoint no rompe si no hay PortfolioSnapshot para el mes (comportamiento
    existente: continúa sin error).

[ ] El endpoint no rompe si no hay posiciones en el mes target (devuelve
    updated=True con todos los contadores en 0).
